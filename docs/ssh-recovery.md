# Host-managed SSH recovery

An optional `ssh-recovery.json` in the application's external config directory
connects a locally approved recovery helper to an exact Profile and server.
It is not a Profile field and is never imported from a server catalog. Ordinary
installations need no registration. Do not distribute this file or any machine
credentials with the application.

After OpenSSH explicitly rejects the public-key authentication path, Radar can
invoke the registered helper once and repeat the failed read-only collection
once after verified success. Successful polls do not add a probe or invoke
recovery. This applies to both scheduled and manually requested reads after an
explicit rejection, under the existing local recovery authorization.
Timeouts, changed host keys, locked private keys, agent failures and too many
authentication attempts do not trigger recovery. The helper must independently
verify the exact endpoint, account, host key and missing authorized key before
making its narrowly approved change.

Registration schema version 1 has a `profiles` object keyed by Profile ID, then
server ID. Each binding contains `connection_fingerprint` (generated by
`vram_radar.service.connection_fingerprint`), absolute `python` and `helper`
paths, and a `files_sha256` map pinning both executables and all helper policy
dependencies. Connection fingerprints cover Profile connection settings and
OpenSSH include dependencies. Connection or file drift stops automatic recovery
until the local authorization is reviewed and rebound.

Radar executes `[python, "-I", "-B", helper]` without a shell, with a minimal
environment, a 90-second process-tree timeout and bounded output. The helper
accepts no Radar-supplied remote command or credential. It must own cross-process
locking, persistent cooldown, credential access and all mutation authorization.
Its only stdout is a JSON object with `server` matching the registered ID and
`status` equal to `ok`, `key_recovered` or `recent_key_verification`; exit code
must be zero. Never print credentials. Raw helper output is not displayed or
logged by Radar.

Concurrent reads share a recent successful recovery. A failed recovery or a
second public-key rejection is retried after at least five minutes, instead of
permanently disabling collection or repeatedly prompting for a password. The
usual saved-password fallback is unchanged for servers without a binding.
Recovery proves access only; it does not restart research jobs or verify their
checkpoint lineage.
