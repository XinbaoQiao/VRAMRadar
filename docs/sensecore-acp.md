# SenseCore ACP 平台接入

ACP 是作业平台，不能登记成一台 SSH 主机。本地开发版支持 `SenseCore ACP`
连接类型，与 SSH、Slurm、本地 GPU 并列；不需要新建 H100 SSH alias 或隧道。

## 登记

1. 在本机安装官方 `sco`，在显存雷达之外完成自己的 CLI profile 认证。
   雷达不初始化账号，也不接收 AK/SK、控制台密码或签名 URL。
2. 在服务器配置中新建条目，连接类型选择 **云任务**。
3. 填写显示名称、workspace、cluster、zone、SCO 程序路径和已认证 profile 名。
   使用自己账号的值，不照抄另一个人的 workspace 或可用区。
4. 保存并连接。连接检查和刷新使用同一个只读任务列表接口；不会提交、停止、
   复制任务、创建计算实例或更改配额。

SCO 可执行文件可位于 PATH，或填写其绝对路径。支持原生程序，不支持 shell
脚本作为替代入口。密码、密钥和 SSH 配置不属于 ACP 条目。

## 当前能显示什么

- 当前 workspace/cluster 下账号**可见**的一页任务，最多 100 条。
- 任务 ID、显示名称、状态以及接口提供的用户、创建时间和原因。
- 明示列表范围，不把可见任务全部认作“我的任务”，不声称完整历史。

当前没有实时显存采集，也未核实可用 GPU 数量：容量与显存保持未知，不显示
虚假的 GPU 行，不参与空闲显存推荐或空闲卡通知。列表接口未提供已核实的
数值字段时，申请 GPU 数也显示未知；规格名称不被解析成实际 GPU 分配。
任务详情中的 Worker 事件、多页历史和任务内 GPU 遥测不属于本版功能。

## 只读命令与故障处理

连接器使用已归档 SCO 帮助和回执确认的命令形式：

```text
sco --profile <name> acp jobs list --workspace-name=<workspace> --aec2-name=<cluster> --format=json --page-size=100 --page-token=1
```

子进程使用 `SCO_ZONE=<zone>`；不通过 shell 拼接命令。调用有超时和输出大小
上限。只提取允许显示的字段，不保存原始 CLI 响应或原始错误内容。

- 找不到 SCO：检查程序路径和安装。
- 认证失败：在平台官方工具中检查所选 profile；不要把凭据粘贴到雷达。
- 拒绝查询：核对 profile、workspace、cluster、zone 与 API 权限，不能仅凭
  403 判定账号整体无权限。
- JSON 格式不兼容：显示明确错误，不能把未知响应当成空队列。

## Harness 用户与配置导入

Harness 的 `H100-SLAI` 可能使用受保护子进程注入凭据，其 SCO 配置本身只有区域，
不是一个可独立认证的 CLI profile。此类账号使用独立的本机
`config/acp-transport.json` 登记：绑定 Profile/server、连接指纹、Python/helper
哈希和命名凭据通道。helper 只允许固定的任务列表请求，通过 `credentialctl`
的受保护子进程使用现有凭据引用；雷达不读取凭据文件，也不复制密钥。

受保护连接设置 `acp_protected_auth=true`。缺少登记、哈希或连接参数变化时
明确阻止查询，不回退到另一 SCO 账号；编辑或重命名也保留这个标志。
登记只能由本机配置，不从共享 catalog 导入。查询页大小按实际桥接显示。
其他账号必须建立自己的受保护绑定，不能复制本机授权文件当作认证。

导入 servers.toml 时，只接受显式配置的 ACP 监控字段。缺少监控字段的 Harness
ACP 条目会给出警告并跳过，不会转换成 SSH，也不会影响可导入的 SSH/Slurm 条目。
用户 Profile 留在应用数据目录，不随公共安装包分发。其他机器需要自己的 SCO
安装和认证；迁移配置不等于迁移账号授权。

## 验证边界

普通开发验证使用离线响应、隔离 Profile 和合成界面。真实账号查询须有用户
授权，单独记录账号可见列表的时间、范围与结果；任务可见不代表实时显存可见。
公开发布和 macOS 打包仍需各自验收。本机安装不等于公开发布。

## 低噪声刷新

云任务没有实时显存。列表无变化时，Radar 会自动拉长轮询间隔（相对普通 SSH 刷新），减少对本机 sco / 远端平台接口的打扰；列表有变化时仍会继续刷新，但不低于约 30 秒一次。
